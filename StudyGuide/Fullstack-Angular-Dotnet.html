0-1 years · Lessons 01-06

Foundations: make the request flow visible

Begin with HTML/CSS, TypeScript, C#, HTTP, and relational basics. Connect Angular components to a small API and a real lab database.

  • Browser-to-database flow and JSON contracts
  • Components, signals, and state ownership
  • C# objects, collections, and invariants
  • ASP.NET Core routing, DI, and middleware
  • SQL keys, EF Core, migrations, and CRUD

Exit check: create one valid order, restart the API, read it again, and explain an invalid request without hiding its error.

Go to foundation concepts
1-3 years · Lessons 07-12

Feature delivery: handle real user behavior

Build predictable forms and request lifecycles. Make permission checks and failures part of the feature, not a later patch.

  • API services and safe error contracts
  • RxJS search, cancellation, and stale responses
  • Typed reactive forms and server validation
  • Routing, resource permissions, and sessions
  • Component, contract, and API integration tests

Exit check: demonstrate a corrected form, a recovered 503, and two users who cannot access each other's orders.

Go to delivery concepts
3-5 years · Lessons 13-18

Production depth: prove safe recovery

Measure the query, recover conflicting edits, prevent duplicate writes, and release a design you can explain and observe.

  • Projection, indexes, pagination, and budgets
  • Optimistic concurrency and two-editor recovery
  • Idempotency, retries, and durable side effects
  • Modular HLD and practical LLD
  • CI/CD, tracing, configuration, and rollback

Exit check: recover a stale edit and a lost response, prove one durable order, and demonstrate a compatible application rollback.

Go to production concepts

Capstone: OrderDesk

Build a separate Angular application and ASP.NET Core API with a relational database. KR7Tech provides the curriculum and exercises; it does not pretend this capstone is already installed or deployed for you.

Angular product/order views -> HTTP contracts -> ASP.NET Core
  -> authorized order behavior -> EF Core -> relational database
  -> explicit result/error -> usable view state

Build in vertical slices

Product list, validated order creation, persistent read-back, owner-only access, editing, then deliberate concurrency and retry behavior.

Keep evidence, not just screenshots

Produce a request trace, DTO contract, schema diagram, permission matrix, focused tests, HLD/LLD diagrams, and a short recovery runbook in your own lab repository.

Daily study loop

Read one concept, trace its flow, implement a small slice, break one boundary, and record what proves recovery. Move on when you can demonstrate the checkpoint, not after memorizing an answer.

Examples are teaching fragments for your separate lab, not complete production identity, payment, or deployment implementations. Use supported framework versions and the official references in each lesson.
